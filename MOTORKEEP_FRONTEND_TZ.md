# MOTORKEEP — Техническое задание на фронтенд

> **Назначение документа.** Это дизайн-система и постраничное ТЗ для проекта MOTORKEEP. Документ написан так, чтобы любая нейросеть (или разработчик) могла сгенерировать новые страницы, неотличимые по стилю от эталона. Все значения токенов в этом ТЗ совпадают с CSS-переменными эталонной реализации один-в-один.

---

## 1. О продукте

**MOTORKEEP** — веб-сервис «дневник автомобиля». Пользователь добавляет свои машины в личный гараж и ведёт их историю: ТО, поломки, покупки, заправки, заметки. По истории считается статистика расходов, пробега и напоминания о следующем обслуживании.

- **Аудитория:** обычные автовладельцы, не профессионалы. Хотят порядок в обслуживании и расходах без Excel.
- **Тон продукта:** спокойный, точный, организованный — как приборная панель хорошей машины. Без перегруза, без «продающих» восклицаний.
- **Задача интерфейса:** быстро вносить записи и так же быстро находить нужное. Данные важнее украшений.

---

## 2. Визуальное направление (зафиксировано)

| Параметр | Решение |
|---|---|
| Стиль | Современный минимализм, много воздуха |
| Тема | **Только светлая** (тёмной темы нет) |
| Акцент | Синий `#2F6BFF`; другие цвета допустимы только как семантика типов записей |
| Стек | **Чистый HTML + CSS + JS**, без сборщиков и фреймворков. Вёрстка переносима на любой стек |
| Устройства | **Равный приоритет** desktop и mobile. Mobile — не «уменьшенная копия», а отдельно продуманный режим |
| Шрифты | **Только свободные и открытые** (лицензия SIL OFL): Space Grotesk — дисплей/цифры, Inter — текст, JetBrains Mono — коды |
| Структура вывода | **Всегда 3 отдельных файла:** HTML + CSS + JS (см. §9) |

**Фирменный элемент (signature):** «одометр» — крупное табличное число текущего пробега шрифтом Space Grotesk с сегментированной полосой-подложкой под ним. Повторяется в карточках авто и на странице авто. Второй опорный приём — лента записей с цветным «рельсом» слева у каждой записи, окрашенным по типу.

## 3. Дизайн-токены

Все токены объявляются как CSS-переменные в `:root`. Новые страницы **обязаны** использовать переменные, а не «сырые» значения.

### 3.1. Цвета — поверхности
```css
--mk-bg:        #F6F8FC;  /* фон страницы */
--mk-surface:   #FFFFFF;  /* карточки, панели */
--mk-surface-2: #F1F5FB;  /* вложенные блоки, hover-фон */
--mk-border:    #E5EAF2;  /* хайрлайны, рамки */
--mk-border-strong: #D4DCE8;
```

### 3.2. Цвета — текст
```css
--mk-ink:   #0E1726;  /* заголовки, основной текст */
--mk-ink-2: #5B6B82;  /* вторичный текст */
--mk-ink-3: #93A1B5;  /* подписи, плейсхолдеры, мета */
```

### 3.3. Бренд — синий акцент
```css
--mk-primary:        #2F6BFF;
--mk-primary-strong: #1B4DDB;  /* hover / active */
--mk-primary-soft:   #EAF1FF;  /* фон-плашка под акцент */
--mk-primary-ink:    #143A9E;  /* текст на soft-фоне */
```

### 3.4. Семантика типов записей (единственные «другие цвета»)
Каждый тип записи имеет основной цвет и мягкую подложку. Эти цвета используются для иконок, тегов, точек в фильтрах и «рельса» записи. Нигде больше цвета вводить нельзя.

```css
--mk-c-service: #2F6BFF;  --mk-c-service-soft: #EAF1FF;  /* ТО          */
--mk-c-repair:  #F0463B;  --mk-c-repair-soft:  #FEECEA;  /* Поломка     */
--mk-c-buy:     #F59412;  --mk-c-buy-soft:     #FEF2E0;  /* Покупка     */
--mk-c-fuel:    #16B364;  --mk-c-fuel-soft:    #E4F8EE;  /* Заправка    */
--mk-c-note:    #8B5CF6;  --mk-c-note-soft:    #F1ECFE;  /* Заметка     */
```
Статусы: `--mk-success #16B364`, `--mk-warning #F59412`, `--mk-danger #F0463B`.

### 3.5. Типографика
```css
--mk-font-display: "Space Grotesk", system-ui, sans-serif;  /* заголовки, ВСЕ цифры, одометр */
--mk-font-body:    "Inter", system-ui, sans-serif;          /* интерфейс, абзацы */
--mk-font-mono:    "JetBrains Mono", ui-monospace, monospace;/* VIN, госномер, коды деталей */
```
**Шкала размеров (px) и где применять:**

| Роль | Размер / вес / шрифт | Применение |
|---|---|---|
| Display L | 40 / 700 / Space Grotesk | Одометр, ключевая цифра экрана |
| H1 | 26 / 700 / Space Grotesk | Название авто, заголовок страницы |
| H2 | 19 / 600 / Space Grotesk | Заголовки секций («История») |
| Stat | 24 / 700 / Space Grotesk | Значения в стат-карточках |
| Body | 15 / 400 / Inter | Основной текст |
| Body S | 13.5 / 400 / Inter | Описания записей |
| Label | 12–13 / 500 / Inter | Подписи, мета |
| Eyebrow | 11 / 600 / Space Grotesk, `letter-spacing:.14em`, uppercase | Надзаголовок над H1 |
| Mono | 13 / 500 / JetBrains Mono | VIN, номер |

**Правило цифр:** любые числа (пробег, суммы, даты-числа, статистика) — шрифтом Space Grotesk c `font-variant-numeric: tabular-nums`, чтобы колонки не «прыгали».

### 3.6. Радиусы
```css
--mk-r-sm: 8px;  --mk-r-md: 12px;  --mk-r-lg: 16px;  --mk-r-xl: 22px;  --mk-r-pill: 999px;
```
Кнопки и чипы — `pill`. Карточки записей и стат-карточки — `lg`. Крупные блоки/hero — `xl`. Иконочные подложки — `md`.

### 3.7. Тени
```css
--mk-shadow-sm: 0 1px 2px rgba(14,23,38,.05);
--mk-shadow-md: 0 1px 2px rgba(14,23,38,.04), 0 6px 18px rgba(14,23,38,.06);
--mk-shadow-lg: 0 8px 28px rgba(14,23,38,.10);
--mk-ring: 0 0 0 4px rgba(47,107,255,.18);  /* фокус-кольцо */
```
Тени мягкие и низкие. Карточки в покое — `sm`, при наведении — `md`. Модалки/FAB — `lg`.

### 3.8. Отступы и сетка
```css
--mk-container: 1160px;  /* max-width контента */
--mk-gutter: 24px;       /* боковые поля (16px на мобильном) */
```
Базовая шкала отступов (px): **4, 8, 12, 16, 20, 24, 32, 40, 48, 64**. Между карточками в ленте — 12. Между секциями — 22–26.

### 3.9. Движение
```
Длительность: 150ms интерфейс, 200–300ms появление блоков.
Easing: ease / ease-out.
Hover карточки: box-shadow sm→md + translateY(-1px).
ОБЯЗАТЕЛЬНО: @media (prefers-reduced-motion: reduce){ *{ transition:none !important } }
```
Анимаций по минимуму: только hover-микровзаимодействия и мягкое появление списков. Никаких параллаксов и «прыгающих» элементов.

## 4. Навигация, сетка и адаптивность

Каркас приложения: **сайдбар слева + оболочка справа** (хедер сверху, контент, футер снизу). Сайдбар фиксированный, контент скроллится.

Брейкпоинты:

| Брейкпоинт | Что меняется |
|---|---|
| `> 1000px` | Десктоп. Сайдбар развёрнут, hero в 2 колонки, стат-карточки в 4 |
| `≤ 1000px` | Hero в 1 колонку, стат-карточки в 2 |
| `≤ 900px` | **Сайдбар → off-canvas drawer.** В хедере появляется бургер, сайдбар выезжает поверх контента со скрим-подложкой |
| `≤ 680px` | Узкий мобайл. Поля 16px, скрываются подпись пользователя и крошка в хедере, FAB становится круглым |
| `≤ 380px` | Стат-карточки в 1 колонку |

**Сворачивание сайдбара (десктоп):** кнопка «Свернуть» внизу сайдбара переключает `body.is-collapsed`. В свёрнутом виде остаются **только иконки** (ширина `--mk-sb-collapsed: 76px`), подписи и заголовки групп скрыты, при наведении на пункт всплывает тултип (`data-tip`). Оболочка `.mk-shell` синхронно сдвигает `margin-left`. Состояние запоминается в `localStorage` (`mk-collapsed`).

**Мобильный режим:** сайдбар по умолчанию спрятан (`translateX(-100%)`). Бургер в хедере открывает его (`body.nav-open`) поверх контента; клик по скриму, по пункту меню или Esc закрывают. Свёртка в иконки на мобильном не используется — в drawer всегда полные подписи.

**Общие правила мобильного:** тач-цели ≥ 44×44px; горизонтальные списки чипов скроллятся (скроллбар скрыт); главное действие — круглый FAB справа снизу; учитывать `env(safe-area-inset-bottom)`.

## 5. Библиотека компонентов

Ниже — все переиспользуемые компоненты с их классами и назначением. Нейросеть собирает страницы из этих блоков, не выдумывая новых паттернов без необходимости.

### 5.1. Сайдбар `.mk-sidebar`
Фиксированное левое меню, фон `--mk-surface`, правый хайрлайн. Структура: шапка `.mk-sidebar__brand` (логотип-марка с градиентом + «MOTOR**KEEP**») → `.mk-sidebar__nav` с группами (`.mk-navlabel` «Меню», «Гараж») из пунктов `.mk-navitem` (иконка 21px + подпись `.lbl`, опционально счётчик `.pill`) → подвал `.mk-sidebar__foot` (Настройки + кнопка `.mk-collapse`). Активный пункт — фон `--mk-primary-soft` + цветной маркер слева через `::before`.
**Сворачивание:** `body.is-collapsed` → ширина `--mk-sb-collapsed`, прячутся `.lbl`, `.mk-navlabel`, `.pill` и текст логотипа; пункты центрируются по иконке; на hover всплывает тултип из `data-tip`. Кнопка `.mk-collapse` переключает класс и пишет состояние в `localStorage`.
**Мобайл (`≤900px`):** сайдбар становится off-canvas drawer (`translateX(-100%)` → `body.nav-open` показывает), поверх — `.mk-scrim`.

### 5.2. Хедер `.mk-header`
Sticky, высота 68px, фон полупрозрачный с `backdrop-filter: blur(14px)`, нижний хайрлайн. Слева: бургер `.mk-burger` (только мобайл) + заголовок страницы `.mk-header__title` с приглушённой крошкой `.mk-header__crumb`. По центру — поиск `.mk-search` (pill-поле с иконкой, плейсхолдером и хинтом `.mk-kbd` «⌘K»; фокус подсвечивает кольцом). Справа: иконка уведомлений `.mk-iconbtn` (с точкой-индикатором `.dot`) и чип пользователя `.mk-userchip` (аватар + имя; имя скрывается на узком экране). Это «современная» шапка — без дублирования навигации (она в сайдбаре), акцент на поиск и контекст.

### 5.3. Футер `.mk-footer` (минималистичный)
Тонкая полоса: верхний хайрлайн, фон `--mk-surface`, по краям — бренд (`.mk-footer__brand`: мини-плашка-градиент + «MOTORKEEP») и копирайт `.mk-footer__copy` слева, ссылки `.mk-footer__links` (Помощь · Конфиденциальность · Контакты) справа. Текст мелкий, цвет `--mk-ink-3`, hover → `--mk-ink`. Никаких колонок-простыней — одна строка, на мобильном складывается вертикально.

### 5.3. Кнопки `.mk-btn`
- `.mk-btn--primary` — синяя заливка, белый текст (главные действия).
- `.mk-btn--ghost` — белая, рамка `--mk-border` (вторичные).
- Форма — `pill`. Иконка слева 17px. Hover у primary → `--mk-primary-strong`.
- **FAB** `.mk-fab` — фиксированная primary-кнопка справа снизу; на мобильном превращается в круг 54px только с иконкой.

### 5.4. Иконочная кнопка `.mk-iconbtn`
Круг 38px, рамка, иконка 24px outline. Hover усиливает рамку и текст.

### 5.5. Чипы-фильтры `.mk-chip`
Pill, рамка. Активный — заливка `--mk-ink` + белый текст. Перед текстом возможна цветная точка `.dot` (цвет типа записи). Контейнер `.mk-chips` горизонтально скроллится.

### 5.6. Тег типа `.mk-tag`
Маленькая pill-плашка рядом с заголовком записи. Цвет = `*-soft` фон + основной цвет типа текстом. Текст: «ТО», «Поломка», «Покупка», «Заправка», «Заметка».

### 5.7. Карточка-герой авто `.mk-hero`
Крупный блок (`r-xl`, тень `md`). Верх в 2 колонки: слева медиа `.mk-hero__media` (фото авто или инлайн SVG-силуэт на градиенте + плашка госномера `.mk-hero__plate`), справа `.mk-hero__body` — eyebrow, H1, подзаголовок, **одометр** `.mk-odo`. Низ — лента мета `.mk-hero__meta` (3 ячейки с хайрлайнами: год, VIN моно, в гараже с).

### 5.8. Одометр `.mk-odo` (signature)
`label` (uppercase, мелкий) → `value` (Space Grotesk 40px, tabular-nums, с единицей «км» приглушённо) → `track` (полоса 6px с сегментированным паттерном `repeating-linear-gradient`).

### 5.9. Стат-карточка `.mk-stat`
Белая карточка `r-lg`. Шапка: цветная иконка-подложка `.mk-stat__ic` (24px, фон `*-soft`) + подпись. Значение `.mk-stat__value` (Space Grotesk 24). Дельта `.mk-stat__delta` (`.up` — красный рост расхода, `.ok` — зелёный/нейтральный). Раскладка: 4 → 2 → 1 колонки.

### 5.10. Запись ленты `.mk-record`
Grid `auto 1fr auto`. Цветной рельс слева через `::before` (`--rail`). Колонки: иконка типа `.mk-record__ic` (подложка `*-soft`) · основное (`__title` + `.mk-tag`, описание `__desc`, мета-строка `__metaline` с пробегом/местом) · правое (`__cost` Space Grotesk, `__date`, кнопка «...» `__more`). На мобильном право переезжает под основное, «...» уходит в правый верхний угол.

### 5.11. Заголовок секции `.mk-section-head`
H2 + счётчик `.count` + распорка + вторичная кнопка (сортировка/фильтр).

### 5.12. Хлебные крошки `.mk-breadcrumb`
Мелкий текст, ссылки `--mk-ink-3` → hover `--mk-ink-2`, разделитель — шеврон-иконка.

### 5.13. Поля ввода (для форм)
Единый стиль: высота 44px, рамка `--mk-border`, радиус `--mk-r-sm`, фон `--mk-surface`, фокус — `--mk-ring`. Лейбл сверху (13px, `--mk-ink-2`). Подсказка/ошибка снизу (12px; ошибка — `--mk-danger`, рамка поля тоже краснеет). Группы: текст, число (пробег/сумма — выравнивание по правому краю, моно/дисплей), select, дата, textarea, загрузка файла (пунктирная зона), сегмент-переключатель типов записи.

### 5.14. Модальное окно / шит
Десктоп — центрированная модалка `r-xl`, тень `lg`, оверлей `rgba(14,23,38,.4)`. Мобайл — bottom-sheet, выезжает снизу, верх скруглён, «ручка» сверху. Используется для быстрого добавления записи.

### 5.15. Пустые состояния
Иконка-подложка по центру, заголовок (что здесь будет), одно предложение-пояснение, primary-кнопка действия. Тон — приглашающий: «Добавьте первый автомобиль», а не «Список пуст».

### 5.16. Тосты / уведомления
Снизу по центру (мобайл — над FAB). Белый, `r-md`, тень `md`, цветная точка статуса. Текст в активном залоге и согласован с кнопкой: кнопка «Сохранить» → тост «Сохранено».

### 5.17. Иконки
Стиль — **outline, viewBox 24×24, stroke 1.8–2.0, скруглённые концы, `fill:none`, `currentColor`**. Не смешивать с залитыми иконками. Базовый набор: гараж/машина, список, график, профиль, плюс, поиск, колокол, гаечный ключ (ТО), треугольник-внимание (поломка), сумка (покупка), колонка/пистолет (заправка), часы (ТО-напоминание), календарь, метка-локация, «···».

## 6. Постраничные спецификации

Для каждой страницы: цель, вайрфрейм (ASCII), компоненты, состояния, адаптив. Сетка контента — max-width 1160px, поля 32/16px.

> **Каркас:** все внутренние страницы (Гараж, Авто, Формы, Профиль) живут внутри оболочки **сайдбар + хедер + футер** (§5.1–5.3). В вайрфреймах ниже показана только область контента — сайдбар и хедер подразумеваются. **Лендинг и Авторизация — standalone-страницы без сайдбара** (у них своя верхняя шапка).

### 6.1. Лендинг (главная, для незалогиненных)
**Цель:** объяснить ценность за 5 секунд и привести к регистрации.
```
┌───────────────────────────────────────────────┐
│ ШАПКА ЛЕНДИНГА: лого · [Возможности][Цены] · Войти ▸ │
├───────────────────────────────────────────────┤
│ HERO                                           │
│   eyebrow: ДНЕВНИК АВТОМОБИЛЯ                   │
│   H1 (display): Вся история машины в одном месте│
│   подзаголовок (1 строка)                      │
│   [Завести гараж →]  [Посмотреть демо]         │
│   справа/ниже: мокап карточки авто с одометром │
├───────────────────────────────────────────────┤
│ 3 КАРТОЧКИ-ЦЕННОСТИ (иконка+заголовок+текст)   │
│   Записи ТО · Контроль расходов · Напоминания  │
├───────────────────────────────────────────────┤
│ КАК ЭТО РАБОТАЕТ — 3 шага (нумерация уместна)  │
├───────────────────────────────────────────────┤
│ Финальный CTA-блок (синяя плашка) + футер      │
└───────────────────────────────────────────────┘
```
**Компоненты:** topbar (упрощённый), `.mk-btn` (primary+ghost), карточки-ценности (как `.mk-stat`, но крупнее), мокап hero — переиспользует `.mk-odo`. **Signature на лендинге:** живой мокап карточки авто с одометром в hero. **Адаптив:** hero в 1 колонку, кнопки на всю ширину, шаги вертикально.

### 6.2. Дашборд «Гараж» (список авто)
**Цель:** обзор всех машин и быстрый переход внутрь.
```
┌───────────────────────────────────────────────┐
│ (область контента внутри каркаса)              │
│ H1: Мой гараж            [+ Добавить авто]      │
│ строка-сводка: N машин · расходы за месяц       │
├───────────────────────────────────────────────┤
│ СЕТКА КАРТОЧЕК АВТО (3 → 2 → 1 колонки)         │
│ ┌───────────┐ ┌───────────┐ ┌───────────┐       │
│ │ фото/силуэт│ │           │ │           │       │
│ │ BMW 320i  │ │  …        │ │  + Доб.   │       │
│ │ одометр   │ │           │ │   авто    │       │
│ │ 3 мини-ст.│ │           │ │ (пунктир) │       │
│ └───────────┘ └───────────┘ └───────────┘       │
└───────────────────────────────────────────────┘
```
**Карточка авто:** медиа сверху + плашка номера, название (H2), мини-одометр, 3 мини-метрики (расходы за год, записей, до ТО), при наведении — тень `md` + translateY. Последняя ячейка — пунктирная «Добавить авто». **Состояния:** пустой гараж → большое пустое состояние с одной кнопкой. **Адаптив:** сетка `repeat(auto-fill, minmax(300px,1fr))`.

### 6.3. Страница авто + лента записей — **ключевой экран**
**Цель:** вся история конкретной машины + быстрый ввод.
```
┌───────────────────────────────────────────────┐
│ breadcrumb: Гараж › BMW 320i                   │
│ HERO авто (медиа+номер | body+ОДОМЕТР | мета)  │
│ 4 СТАТ-КАРТОЧКИ (записей · расходы · расход · ТО)│
│ section-head: История · 48 · [Сортировка]      │
│ ЧИПЫ: Все · ТО · Поломки · Покупки · Заправки   │
│ ЛЕНТА .mk-record × N (рельс по типу)           │
│ FAB: + Добавить запись                          │
└───────────────────────────────────────────────┘
```
Это центральный экран продукта — основной образец разметки и классов. **Состояния:** нет записей → пустое состояние внутри секции; загрузка → 3–4 скелетона карточек. **Адаптив:** hero 1 колонка, стат 2→1, записи перестраиваются, FAB круглый; сайдбар уходит в drawer.

### 6.4. Формы: добавить авто / добавить запись
**Цель:** внести данные за минимум действий. На десктопе — отдельная страница или модалка; на мобильном — bottom-sheet.

**Добавить запись:**
```
┌─────────────────────────────┐
│ Новая запись            ✕   │
│ ТИП (сегменты-чипы):        │
│  [ТО][Поломка][Покупка]...  │  ← выбор красит акцент формы
│ Название            [____]  │
│ Дата       Пробег, км       │
│ [_____]    [________]        │
│ Сумма, ₽   Место/сервис     │
│ [_____]    [________]        │
│ Описание (textarea)         │
│ [_______________________]   │
│ Фото/чек (пунктирная зона)  │
│            [Отмена][Сохранить]│
└─────────────────────────────┘
```
**Добавить авто:** марка, модель, год, тип кузова, двигатель/КПП, VIN (моно), госномер (моро), текущий пробег (крупное число), фото. **Правила:** лейблы сверху; числовые поля выравнены вправо и набраны дисплей-шрифтом; обязательные помечены; ошибки под полем + красная рамка; primary-кнопка действия повторяет глагол («Сохранить» → тост «Сохранено»). **Адаптив:** поля в 1 колонку, sheet снизу, кнопки прилипают к низу.

### 6.5. Авторизация (вход / регистрация)
**Цель:** минимальный порог входа.

**Компоненты:** карточка-форма `r-xl` тень `md`, поля 5.13, primary-кнопка на всю ширину, ссылка-переключатель вход/регистрация, соц-кнопки как `--ghost`. **Адаптив:** ≤680px бренд-панель скрывается, остаётся центрированная форма-карточка. **Тексты ошибок:** конкретные («Неверный email или пароль»), без извинений.

**Цель:** управление аккаунтом и предпочтениями.

## 7. Контент и копирайтинг

- **Активный залог, sentence case.** Кнопка говорит, что произойдёт: «Сохранить», не «Отправить». Глагол сохраняется по всему флоу: «Сохранить» → тост «Сохранено».
- **Имена — от пользователя, не от системы.** «Напоминания», а не «крон-задачи».
- **Пустые экраны — приглашение к действию,** а не констатация пустоты: «Добавьте первую запись — и здесь появится история».
- **Ошибки не извиняются и конкретны:** что случилось и что сделать.
- **Без филлера и кликбейта.** Числа и факты вместо прилагательных: «8.4 л на 100 км», а не «отличный расход».
- Денежные суммы: `214 600 ₽` (неразрывные пробелы как разделители разрядов). Пробег: `86 420 км`. Даты в ленте: «12 июня 2026».

## 8. Доступность (обязательный пол качества)

- Контраст текста к фону ≥ 4.5:1 (основной текст `--mk-ink` на белом — проходит).
- Видимый фокус на всех интерактивных элементах: `:focus-visible { box-shadow: var(--mk-ring) }`.
- Семантические теги: `header/nav/main/section/article`, кнопки — `<button>`, у иконочных — `aria-label`.
- Тач-цели ≥ 44×44px на мобильном.
- `prefers-reduced-motion` отключает анимации.
- Цвет типа записи **дублируется текстом тега** — не полагаться только на цвет.
- Изображения авто — осмысленный `alt`; декоративный SVG — `aria-hidden` либо `role="img"` + `aria-label`.

## 9. Технические требования к коду

### 9.1. Структура вывода — всегда 3 файла
Любая страница отдаётся **строго тремя файлами**, без исключений:

| Файл | Назначение |
|---|---|
| HTML | Только разметка. Подключает шрифты, общий CSS- и JS-файл. Никаких `<style>`-блоков и инлайновых обработчиков |
| CSS | Все стили: `:root`-токены + компоненты. Один общий файл на весь проект |
| JS | Всё поведение: свёртка сайдбара, мобильный drawer, фильтры, поиск и т.д. Без зависимостей, vanilla JS, обёрнут в IIFE |

Допускается только точечный инлайн-`style` для значений данных (например `--rail` цвета записи или `background` иконки типа) — структурные стили туда выносить нельзя. Общие CSS- и JS-файлы переиспользуются между всеми страницами проекта без копирования.

### 9.2. Шрифты — только свободные и открытые
Разрешены **исключительно** опенсорсные шрифты под свободной лицензией (SIL OFL / Apache). Базовый набор: **Space Grotesk**, **Inter**, **JetBrains Mono** — все три имеют лицензию SIL OFL и доступны бесплатно (Google Fonts или самохостинг). Подключать через `<link>` с `preconnect` либо локально (`@font-face`). В `font-family` всегда указывать системный fallback. Платные/проприетарные гарнитуры запрещены.

### 9.3. Прочее
- **Чистый HTML/CSS/JS.** Без сборщиков и CSS-фреймворков. Разметка переносима в React/Vue (компонент = блок из §5).
- Классы с префиксом `mk-`, БЭМ-подобно (`.mk-record__title`). Следить за специфичностью селекторов (особенно паддинги/маржины секций — не давать им взаимно гаситься).
- Все цвета/радиусы/тени/шрифты — **только через CSS-переменные**. Прямые хексы вне `:root` запрещены.
- Иконки — инлайн-SVG `currentColor`, стиль outline 24×24, stroke 1.8–2.0.

## 10. Чек-лист для нейросети перед выдачей новой страницы

1. Вывод — ровно **3 файла** (HTML + общий CSS + общий JS), без `<style>`-блоков в HTML?
2. Шрифты — только свободные/открытые (Space Grotesk, Inter, JetBrains Mono), с системным fallback?
3. Объявлены все `:root`-токены (или подключён общий CSS-файл)?
4. Фон страницы `--mk-bg`, карточки `--mk-surface`, тема светлая — тёмной нет?
5. Все числа набраны Space Grotesk + `tabular-nums`?
6. Новые цвета **не** вводились (только бренд-синий и семантика типов записей)?
7. Есть сайдбар (со свёрткой в иконки) + современный хедер на десктопе, drawer + бургер на ≤900px, круглый FAB на мобильном?
8. Минималистичный футер с хайрлайном сверху на месте?
9. Карточки используют радиусы и тени из токенов; hover = `md` + `translateY(-1px)`?
10. Кнопки/чипы — `pill`; primary синяя, вторичные — ghost?
11. Есть состояния: загрузка (скелетоны), пусто (приглашающее), ошибка (конкретная)?
12. Фокус виден, `aria-label` у иконочных кнопок, контраст в норме, `prefers-reduced-motion` учтён?
13. Тексты в активном залоге, кнопка и её тост согласованы по глаголу?
14. Проверена раскладка на 1280px, 768px и 390px?

> Если все пункты «да» — страница соответствует MOTORKEEP. Эталон стилей и поведения — общий CSS- и JS-файл проекта.
